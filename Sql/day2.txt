Constraints:
------------
While creation of the tables on top of any columns if you want to restrict the data as per your requirements we can go for constraints.

Different types of constraints:
-------------------------------
1. unique : As per the requirement if you dont want to allo any duplicates on top of a column then we can use unique constraint.

2. not null: As per the requirement if you want to restrict null values or unknwon values in to a column then we can able to notnull constraint.

Note: as per the requirement on top of the same column we can able to apply any number of constraints.

null: unknown values or non defined values or empty value

3. check: As per the requirement if you dont want allow any values based on specific condition then we can able to use check constraint.

in emp table I want to allow only the employee whose salaray > 500 ==>  sal>500


4. Primary key: If you apply PK constraint on top of a column then it will not allow duplicates and also it will not allow null values.
	- In a table if you want to identfy a unique records based on your requirement then we need to apply PRIMARY key constraint.
	- In a table we can able to maintain only one PK constraint.
Primary key : Unique+not null


5. Foreign key: TO maintain relationship between multple tables in database system we need to maintain Foreign key constraint.

6. Default : If we are not passing any values to a specific then by default you want to allow a default values, for this kind of requirements we can able to use default constraint.

can we able to replcase unique constraint with PK --> NO
can we able to replace not null with PK --> NO
can we able to replace notnull+ unique with PK --> Yes (terms and conditions - that table should not contain any other PK)

In real time projects while creation of the tables do we need to worry about which constraint we need to apply on each and every column ==> Data modeller (PDM)
